# VectorCompare

A responsive Django camera application that:

- asks the visitor for a username and stores it in the Django session;
- opens the device camera in the browser;
- works on laptop and mobile layouts in portrait and landscape;
- captures a JPEG every 3 seconds while streaming;
- sends each snapshot to Django;
- uploads each snapshot to an Amazon S3 bucket; and
- names each object as `YYYY-MM-DD_HH-MM-SS-ffffff_username.jpeg`.

The microseconds prevent two concurrent uploads for the same username from accidentally
using the same S3 object key.

## 1. Create the environment

```bash
python -m venv .venv
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1

pip install -r requirements.txt
```

## 2. Configure environment variables

Copy `.env.example` to `.env` and update it:

```bash
cp .env.example .env
```

Required:

- `DJANGO_SECRET_KEY`
- `AWS_S3_BUCKET_NAME`
- `AWS_REGION`

For local development, Boto3 can use AWS credentials from your normal AWS credential
chain. Do not place AWS credentials in browser JavaScript or commit them to Git.

For production, prefer an IAM role attached to the server/container.

The IAM identity needs permission to put objects into the selected bucket, for example
`s3:PutObject` on the intended bucket/prefix.

## 3. Initialize Django

```bash
python manage.py migrate
```

## 4. Run locally

```bash
python manage.py runserver
```

Open:

`http://127.0.0.1:8000/`

Camera APIs are available on localhost in modern browsers. For access from a phone or
another device over the network, deploy behind HTTPS. Browsers generally require a
secure context for camera access.

## 5. Production configuration

Set:

```env
DJANGO_DEBUG=False
DJANGO_ALLOWED_HOSTS=your-domain.example
```

Use HTTPS and a production WSGI/ASGI server plus a reverse proxy or managed platform.
For an HTTPS deployment, also consider enabling Django's secure session/CSRF cookie
settings.

## Routes

- `GET/POST /` - username entry
- `GET /camera/` - camera interface
- `POST /snapshot/` - JPEG upload endpoint
- `POST /logout/` - clears the session

## Notes

The username is taken from the server-side Django session when an image is uploaded.
The browser cannot choose another username simply by modifying the snapshot request.

The server validates that the uploaded object is a JPEG and rejects snapshots larger
than 8 MiB.

The S3 timestamp is generated by the Django server in UTC.
